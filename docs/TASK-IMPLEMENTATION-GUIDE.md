# 后续任务实施指南

面向接手本仓库的任何模型或制作人员。先读根目录 `AGENTS.md` 和 [当前设计方案](DESIGN-SPEC.md)，再开始改动。本指南提供实施顺序；不能用旧的2.0图稿或旧线上站点覆盖当前本机方案。

## 1. 接手时先确认

1. 看用户这轮指定的章节与目标。当前认可的是秦朝样章的整体方向；没有新指示时，不批量改其他章节或重新设计主页。
2. 看 `git status`，保护已存在的未提交工作。跨多个文件修改前，为相关源文件和原图留备份；不覆盖无法确认归属的内容，不自动提交或推送。
3. 看当前本机页面 `http://127.0.0.1:4173/`，确认显示的任务和素材确实是最新版本。不能以构建成功代替实际看页面。
4. 看源稿、素材登记、当前组件和语音脚本，优先复用；不要先写新框架、换TTS引擎或安装新服务。
5. 按 [任务模板](design/TASK-TEMPLATE.md) 写清每步看、听、做和反馈的关系，再编辑正式源文件。

已确定的主页、角色、两项选择方式、家长折叠、预生成语音和本地交付不需要反复询问确认。遇到真正缺失的学习目标、来源、用户偏好或权限时，说明具体缺口并继续不依赖它的工作；不能把历史缺图当作编造材料的理由。

2026-09-15用户澄清：取消的是多端适配，当前指定屏幕尺寸仍需保证。用户给出宽高时按指定值；未给出时读取当前浏览器内容区域的实际宽高并记录，作为本轮唯一目标尺寸。可指定该尺寸复现布局问题，临时调整后恢复原状；不自动增加手机、平板、桌面尺寸矩阵，旧QA与旧线框图也不触发多端工作。

## 2. 文件优先级与修改入口

- 根 `AGENTS.md`：当前产品原则与边界。
- `docs/DESIGN-SPEC.md`：已经认可的设计基线；`BUILD-PLAN.md`、`TODO.md`：当前范围和剩余工作。
- `content/focused-quests.json`：可见34章的题干、故事、反馈、两项选择、表现方式和结束动作。
- `content/chapters/*.md`：事实底稿、编辑背景、正式长声音原稿；修改事实后同步。
- `content/sources.json` 与 `content/assets/*.json`：事实引用和素材身份、路径、许可。
- `content/voice-interface-lines.json`、`content/voice-pronunciations.json`：公共声音参数和词语级校音。
- `public/content/**`、`content/runtime/**`、`public/audio/voice-lines.json`、`public/audio/voice/manifest.json`：生成文件，不手工改。

完整库103章和当前34章展示包分别保留；隐藏不等于删除或审核通过。先确认是否属于可见范围，不为了让新入口“出现”而绕过展示清单。

## 3. 制作一章的最小闭环

### 内容与事实

- 先填“主旨—证据—互动—理解结果”表。一个核心问题要能在结尾用指图、选择、动作或短句回答；逐项标明真图能证明什么、文献支持什么、孩子做这一步会理解什么。三项缺一时先补内容设计，不以美术或小游戏数量代替。
- 对关键人物、政策与年代做时间核对，区分建立朝代、制度开始和制度改变。例如汉朝建立、五铢始铸、铸币权收归中央是不同节点，不能用同一个年份混讲。适龄简化不能改变事实或凭空补动机。
- 定义一个核心问题、一句带走的话、一个可观察的结果。
- 检查历史对象的主要用途是否在开场、儿童旁白与结尾出现。建筑/工程不能只讲施工：例如长城应说明抵御外来进攻及城墙、关口、守卫的配合；不以增加无关操作代替解释。
- 找到能直接支持主线的原文，记录机构、标题、URL、来源ID与页码/段落。先有依据，再写儿童表达。
- 五步固定为 `time / beginning / journey / change / takeaway`，叙事根据题材变化。第一步既要有主题依据，也要能定位时间；短语音先给可用的年代线索，不能只让儿童依赖小字或猜测。
- 人物、诗词或地点在故事中承担具体作用；不能把它们只列在封面，也不能强编人物亲历或因果。
- 把详细解释和材料局限放进家长层。不要用很多小字补救儿童层缺乏画面或操作的问题。

### 图片与工具

- 为每张图先写用途：证据、故事场景，还是学习道具。查过已有素材后再申请新图。
- 真材料核对身份和年代，照片另核对作者/许可。相关但年代不同的材料必须直接标注差异，例如“汉代，秦之后”。
- 同题两项在表现类型、风格、视角、背景、大小、标签和清晰度上可比较；场景中的选中物与选项复用同一表现。
- 角色改动先读 `CHARACTERS.md`；主页、任务相聚、结束和分享图一起检查。旧图保留，新图使用版本路径。
- 生成图片使用图片工具；原图必须先看，提示词写明编辑目标和不变量。功能性刻度和操作关系复用代码组件，不让图片模型画需要精确判断的刻度。
- 新图保存到项目内并登记；不能只留工具默认输出路径。保留实际提示词、编辑次数与验看结果。

### 页面与交互

- 沿用历史站、故事卡、封面、五步、结束的入口与进度。禁止用章节ID硬编码第二套导航或完成状态。
- 优先用现有 `presentation`、`narrative`、`interaction`、`objectView` 配置。新增玩法时同步扩展共享组件、类型、生成器与校验支持的类型列表。
- 当前工坊 `objectView` 支持 `era / ruler-pair / ruler / weight / prop / scene-card / circle-model`。故事图卡从登记的插画中裁取操作人物，选中后主场景同步更换；裁取需标明原图尺寸与范围，不能混入不同风格的照片。真实照片从 `inspection` 显示，不再用 `objectView: evidence` 充当普通工具选项。
- `scene-find`的`hotspots`使用原图归一化坐标，`rounds`逐问登记目标、问题、对错回应与声音。热点与原图使用同一坐标层；裁切空白时不得让焦点滚动导致图片和热点跳位。中间一问答对不标整步完成，全部问完才调用共享完成机制。末轮完成只标当前目标为正确，不能把所有未选候选一起涂绿。
- `inspection` 绑定实际素材、简短说明声音和出处链接；不能随手取 `evidence[0]` 给所有步骤作图。
- 多角度照片写入章节`photoAlbum.photos`，逐张维护`assetId / period / observation / narration / sourceIds / sourceLinks`。`inspection.openAlbum`从当前材料进入同一相册，`focusAlbumPhoto`统一切换图、文、年代、声音与出处；不用相册增加必答步骤。先验看原图，避免大段文字标牌或大量空景挤掉要观察的对象。
- 正误回应、图形状态、声音与下一步按钮同步。错误状态有叉号/文字/明显边框，能够重试。
- 拼接/摆放模型的判定与绘制共用同一坐标和尺寸比例；测试吸附后两端是否真对齐。留出固定反馈高度，避免错误提示让操作物在手指下跳动。
- 结束按钮按真实行为命名，主要操作位于亲子扩展之前；使用FinishNavigation，统一图标/文字排布，不混用首页CTA样式。拖动提供箭头和键盘替代。

### 声音

- 先看现有 `VOICE-WORKFLOW.md`。当前游戏用edge-tts在线合成后本机播放；F5-TTS是另有的本地方案，不擅自切换。
- 交互步骤优先用短引导 `audio.lead`；`look-listen`阅读页使用 `audio.intro`完整故事。播放、重听与下一步统一走 `stepVoiceIds`，不能只播放“请看看”而把故事留给孩子读字。阅读页一次继续，不另点“听完/答对”确认。
- 多问步骤开场播放短故事和第一问，换问只读新问题；答错、答对与重听对应当前回应。重新开启声音时保留当前问题/回应，不回到第一问；章节或步骤切换后清除旧语音指向。
- 只变图片/布局时不重新生成语音；改过台词、校音或音色才运行 `npm run voice:update`。
- 校音按完整词语，保持显示文本和稳定ID。检查音频清单是否匹配合成输入；不能把“量一量”的改读扩散到“度量衡”。
- 合成使用暂存文件，全部成功后替换。不得为一次供应商失败删除原声音包；不调用无关的新GPT语音流程。

## 4. 必须完成的验证

按改动选择必要工作；仓库要求的基础检查照常完成，不新增只重复实现的测试。

```bash
npm run content:validate:assets
npm run content:pack
npm test
npm run lint
npm run typecheck:app
git diff --check
```

`npm test`本身包含打包和构建。`npm run typecheck:app`使用仓库内的tsconfig.app.json检查全部界面文件，避免依赖某位模型留在临时目录里的配置；它不声称完整Cloudflare运行环境类型已验收。最后一次源稿修改后确认运行包已经更新；检查通过后不要没有原因地重复全部流程。

`npm run content:audit`检查全库103章/515步结构、图声路径与同组选项技术呈现一致性。它可以拦住混入照片入口、未知道具类型、SVG和位图混搭等问题，但不能判断两张位图是否画风一致、史料是否有力或孩子是否理解。视觉与内容复核仍要人工完成。

实际浏览器按修改范围至少检查：

- 新题的进入、错误选择、正确选择、重听与下一步；选中对象与主画面是否一致。
- 图片层能打开和关闭，家长来源入口可用，真人/文物与插画身份可分清。
- 在本轮目标尺寸下检查画面、信息层次和主要操作：主按钮不越界、被裁切或遮挡，页面不意外横向溢出；图文、选项、反馈与声音相互对应。
- 涉及拖动时实际拖一次，并检查箭头/键盘替代；涉及结束页时检查折叠前后以及两个按钮的实际去向。
- 涉及角色时，在当前页面检查脸、发型和配饰能否区分，不能只看原图。
- 涉及语音时，检查播放、暂停续播、重听、旧声音取消、台词绑定，并试听重点词。只查文件不能声称人耳校音通过。

仅改图片时可以只检查图片落位、角色与资源加载，不必重复未改的所有关卡操作。保留修改前后、目标尺寸、检查范围、结果和未覆盖项；当前尺寸的问题需处理，多端适配不列为待补门禁。

## 5. 本机交付与异常处理

- 首先检查4173端口与已有进程。已有服务就复用；需要启动时用 `npm run dev -- --port 4173 --hostname 127.0.0.1` 或本机启动脚本。
- 若4173被占，先确认是否就是本项目；不能静默跳到另一个端口再继续给旧链接。
- 用实际HTTP结果和浏览器地址确认本机页面，检查一个新变化确实可见。返回链接必须为本地地址。
- 不调用会展示旧线上Site卡片的工具；不提供ChatGPT Site链接。用户的本机交付要求覆盖技能默认的线上站点展示流程。
- 在Codex内打开时，优先用确切本地URL。需要复用标签时使用实际应用标签ID，不把浏览器自动化内部句柄当作应用标签ID。返回“queued”只能说明排队，不能声称用户已看到页面；再查实际标签URL和页面。
- 清理自己创建的重复临时标签，保留当前本机预览。不要关闭无法确认归属的用户标签。

## 6. 留给下一位模型的交付物

更新 `PROGRESS.md`、`TODO.md`，用户可见变化更新 `CHANGELOG.md`。设计原则变化同步 `DESIGN-SPEC.md`，新增问题同步 `DESIGN-IMPROVEMENTS.md`；长期约束才写入根 `AGENTS.md`。

检查记录放在 `docs/qa/<日期-主题>/`，最少包含：

- 用户本次目标、修改范围、已认可与尚待确认的部分；
- 相关源文件、最终素材、来源与许可、实际图片提示词；
- 运行过的检查、本轮目标尺寸及来源（用户指定或当前浏览器实测）、本机页面与实际操作、结果和未覆盖项；
- 旧素材/备份位置、剩余问题与下一步建议。

交付文字说明改了什么、实际验证了什么、还有什么没完成，再给本地预览和主要文档。不要把源码检查写成页面验收，也不要把家长提示后的完成写成儿童独立理解。


### 汉朝五铢钱复用示例

`scene-find`除找人也能找工具：用`interaction.ariaLabel`说明对象，两轮分别指定目标与声音。需要钱范学具时使用`slide-fit`的`coin-mould`场景，`placement: panel`和`modelLabel`说明其为学习图。`presentation.sceneAspectRatio`按实际图片中的关键人物和工具确定裁切，不能把模具或秤裁掉。真实照片仍放在`inspection/photoAlbum`中，不混进同组插画选项；尺寸参数不新增多端验收范围。


### 不强制拖动的章节

张骞出使章使用见闻选择、两轮驿站找人和回信情境；蔡伦章使用原料辨认与书写材料比较。操作种类服从历史目标，不强制每章塞入一个SlideFit。结束亲子任务无需屏幕学具时，配置`familyMode: actions`，提供可回看的故事图、相册入口和亲子动作，不落回默认尺子或旧小游戏。

同一大场景裁出多个选项时，`interaction.selectionFraming: detail`可在选中后放大对应局部。图卡与主画面共用SceneCardArt裁取坐标，确保选哪项就显示哪项；其他已认可章节的全景切换保持原样。


## 三国两晋南北朝新增的可复用约定（2026-09-19）

- `circle-refine`登记12、24边两段`refinements`及声音，最后一级才完成；`circle-model.sides`与`visual.sides`必须一致。绘图统一引用`app/circle-geometry.ts`，同一圆的半径不变，不能只换数字标签或以近似外观代替实际边数。家庭`practice.scene: circle-refine`支持复位，不能改变章节进度。
- 器物、书页、壁画局部可用`inspection.framing: object`完整显示；宽景与器物分别选择构图，检验缩图仍能看见观察对象。
- 旧数学书的后世印本、文物模型、宗教故事和教学新画都直接标注身份。原始文献正文、图片元数据、照片许可分别核对，不用一个来源承担所有证明。
- 权威来源年份不一致时核查事件过程及口径，记录页码；如迁都宣布、营建、正式迁入是不同节点，不把不同年份默默拼接。儿童可用世纪定位，家长层保留过程和依据。
- 修改源JSON后，已进入的章节可能仍持有旧数据。需要退出并刷新再进入，确认新的图片或声音ID确实出现在当前本机页面。


## 隋朝制作补充（2026-09-19）

- 语音登记不得为空，包括阅读页的源稿回应字段；打包现会在联网合成前拒绝空语音。先修源稿，不用静音文件占位。
- `presentation.story.reunionAspectRatio`可按实际结尾图的叙事对象设置；未配置的章节保持原有尺寸。取景检查不仅看人脸，也要看手指所指的书、工具或物件；当前尺寸主按钮仍需可见。
- 相册边界与素材备注完全相同的段落只输出一次；不同材料限制仍保留。园区绿篱、保护棚等现代展示不能混称原遗迹本体。


## 唐朝两章的复用补充（2026-09-19）

- 在真实材料上做找图题时，`interaction.imageLabel: 实物照片`与`visualAssetId`绑定已清权外部实物素材；生成器拒绝把项目自制图标成照片。其他故事默认仍标故事插画。
- 同一朝代内两个事件的时间线可用`objectView.marker: coin / calendar`，主时间线和选项共用同一标记；符号为现代学具，不作文物。不得用两张同样的朝代图把区别全部压给小字；年代语音照常提供。
- `photoAlbum.photos[].crop`记录原图坐标和尺寸。PhotoCrop在主图、缩图、入口预览共用同一范围，使用独立clipPath，越界由打包拒绝。备注写“原图局部”，文件本身保留；相关CSS只作用于应有层级，不能把主图高度继承给缩图。
- 书影先核对书的版本、页码与内容所述年代。序末日期不一定是刊刻日期；不同馆藏版本不能拼成同一本。

## 后续17章新增复用入口（2026-09-21）

- `interaction.kind: history-lab`配`lab.kind`和`lab.stages`，支持polities/printing/compass/roof/engine。阶段数量与模型由`app/history-lab-model.ts`定义；`HistoryLab.tsx`只负责绘制和操作。沿用ObjectWorkbench完成回调，不新增章节状态机。进入读`audio.intro`，每阶段独立语音；未完成、动画中均不能提前前进或重复启动。
- `interaction.imageCrop`适用于scene-find真图局部，记录x/y/width/height/sourceWidth/sourceHeight；`sceneAspectRatio`必须匹配取景比例。热点按局部图归一化，不按整张原图。使用SVG视窗保留原始文件，完整证据入口不裁取。构建拒绝越界与比例不一致。
- `presentation.story.reunionFit: contain`供书页靠近画底的结束图使用；默认值保持既有章节。完整结束回答和亲子展开区排在FinishNavigation之后。
- 图卡裁取同时实看缩图和选中大图：主对象完整，不能把旁人的半张脸带进边缘；热点围手、工具或相关区域，不遮脸。
